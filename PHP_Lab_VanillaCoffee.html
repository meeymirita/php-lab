2. Типы, приведение, strict_types #

2.1 declare(strict_types=1) — переключатель на весь файл

По умолчанию PHP — язык со слабой типизацией: параметр с аннотацией int тихо примет строку "5" и приведёт её. declare(strict_types=1) в начале файла (обязательно первой строкой после <?php) отключает это ТОЛЬКО для вызовов функций/методов ИЗ ЭТОГО ФАЙЛА — не глобальная настройка, а атрибут файла.

<?php
declare(strict_types=1);

function addQty(int $a, int $b): int { return $a + $b; }

addQty(2, 3);          // 5 — ок, оба int
addQty('2', 3);        // TypeError: Argument #1 ($a) must be of type int, string given
                         // БЕЗ strict_types эта же строка тихо сработала бы: '2' привелось бы к 2

Важная деталь: strict_types проверяется в файле, откуда идёт ВЫЗОВ, а не в файле, где объявлена функция. Если addQty объявлена в файле со strict_types, но вызвана из файла БЕЗ него — сработает слабая типизация вызывающей стороны.

2.2 == vs === в PHP: таблица, которая изменилась между PHP 7 и PHP 8

0 == 'abc'         // PHP 7: true (строка "abc" приводилась к 0)  |  PHP 8: false — ИЗМЕНЕНО, теперь 0 приводится к '0', сравнение строк
0 == ''            // PHP 7: true   |  PHP 8: false — та же причина
0 == '0'           // true в обеих версиях — '0' валидно приводится к числу 0
'1' == '01'        // true — обе валидные числовые строки, сравниваются как числа: 1 == 1
'10' == '1e1'      // true — '1e1' валидная числовая строка (10 в экспоненциальной записи)
100 == '1e2'        // true — та же причина
null == false       // true — оба приводятся к false
null == 0           // true — null приводится к 0 (В ОТЛИЧИЕ от JavaScript, где null == 0 это false!)
'' == null          // true
[] == false          // true
🔬 Под капотом: PHP 8 vs JS: null == 0 — противоположные ответы в двух языках

В JavaScript (JS-лаба, раздел 3) null == 0 — false: спецификация ECMAScript говорит, что null равен ТОЛЬКО undefined и больше никому. В PHP null == 0 — true: PHP приводит null к числу 0, затем сравнивает как числа. Одинаковый синтаксис (==), одинаковая идея «нестрогое сравнение», но разные конкретные правила — единственный надёжный способ не путаться между языками — всегда проверять конкретный случай в документации, а не полагаться на интуицию, перенесённую из другого языка.

2.3 Приведение типов: явное и правила

(int) '42abc'       // 42 — PHP берёт числовой префикс строки, не бросает ошибку (в отличие от Number() в JS, который дал бы NaN)
(int) 'abc'         // 0
(int) 3.9            // 3 — ОТБРАСЫВАЕТ дробную часть, не округляет!
(bool) '0'           // false — единственная НЕпустая строка, которая ложна
(bool) '0.0'         // true — а вот это уже истинно! Строка "0.0" не равна строке "0"
(bool) []             // false
(bool) [0]            // true — непустой массив истинен, даже если единственный элемент — 0
(string) true         // "1"
(string) false        // "" (пустая строка)
(string) null         // "" (пустая строка, БЕЗ warning в 8.x для обычных операций)

2.4 Union types, nullable, mixed (PHP 8+)

function formatPrice(int|float $amount, ?string $currency = null): string {   // union type + nullable через ?
    return number_format($amount, 2) . ' ' . ($currency ?? 'RUB');
}
formatPrice(250);              // "250.00 RUB"
formatPrice(250.5, 'USD');     // "250.50 USD"

function processAny(mixed $value): void { /* mixed = "любой тип", ноль проверок компилятором, честная альтернатива отсутствию типа */ }

Правило лабы: всегда declare(strict_types=1) и всегда === в новом коде (то же правило, что в JS-лабе для == vs ===) — единственное осмысленное исключение для == в PHP отсутствует настолько же чётко, как x == null в JS, поэтому здесь правило даже строже.

3. Массивы: значения с copy-on-write, функции, by-value vs by-reference #

3.1 PHP-массив — не то же самое, что JS-массив

В JavaScript массив — объект, передаётся по ссылке (JS-лаба, раздел 4: { ...obj } — поверхностная копия, которую приходится делать явно). В PHP массив — значение, как число или строка: присваивание копирует его целиком (логически), и функция получает СВОЮ копию, если не указано иное.

<?php
declare(strict_types=1);

$a = [1, 2, 3];
$b = $a;              // "копия" — но НЕ обязательно физическое копирование памяти прямо сейчас (см. "под капотом")
$b[] = 4;
var_dump($a);          // [1, 2, 3] — НЕ ИЗМЕНИЛСЯ
var_dump($b);          // [1, 2, 3, 4]

function addItem(array $items): array {         // массив передаётся ПО ЗНАЧЕНИЮ
    $items[] = 'new';
    return $items;
}
$original = ['a', 'b'];
$modified = addItem($original);
var_dump($original);    // ['a', 'b'] — функция не смогла изменить оригинал
var_dump($modified);     // ['a', 'b', 'new']

function addItemByRef(array &$items): void {      // & — ПО ССЫЛКЕ, явно запрошено
    $items[] = 'new';
}
addItemByRef($original);
var_dump($original);      // ['a', 'b', 'new'] — теперь изменился, потому что явно передали по ссылке
🔬 Под капотом: copy-on-write: почему $b = $a не копирует память сразу

PHP не копирует содержимое массива в момент присваивания $b = $a — оба указывают на одну внутреннюю структуру данных (zval с refcount), пока никто её не меняет. Физическое копирование происходит ЛЕНИВО, в момент первой попытки ИЗМЕНИТЬ одну из копий ($b[] = 4) — движок видит refcount > 1, делает реальную копию именно в этот момент, и только тогда изменения расходятся. Это оптимизация: если вы просто читаете $b, никогда не меняя, копирование не произойдёт вообще, экономя память и время. Механизм называется copy-on-write (COW) и специфичен для PHP — в JS у объектов/массивов нет аналога, там всегда общая ссылка, пока не скопируете явно.

3.2 Индексированные и ассоциативные — на самом деле одна структура

$indexed = ['espresso', 'latte', 'cappuccino'];              // ключи 0, 1, 2 — НЕЯВНО

4. Строки: multibyte, sprintf, регулярки #

4.1 mb_* функции: почему обычные strlen/substr ломаются на кириллице

$name = 'Латте';
echo strlen($name);          // 10 — а не 5! strlen считает БАЙТЫ, каждая кириллическая буква в UTF-8 занимает 2 байта
echo mb_strlen($name);        // 5 — правильно, считает СИМВОЛЫ

echo substr($name, 0, 2);      // "Ð" (мусор) — обрезал байты посередине многобайтового символа
echo mb_substr($name, 0, 2);    // "Ла" — корректно

echo strtoupper($name);         // "Латте" — НЕ РАБОТАЕТ для не-ASCII без указания локали
echo mb_strtoupper($name);       // "ЛАТТЕ" — работает корректно для UTF-8

Правило лабы: для любого текста, который потенциально не чистый ASCII (то есть почти всегда) — только mb_* функции. Забыть mb_ префикс на кириллице/эмодзи — один из самых частых и незаметных багов в PHP-проектах с русским языком.

4.2 sprintf — форматирование без конкатенации

$price = 1234.5;
sprintf('%.2f ₽', $price);              // "1234.50 ₽"
sprintf('%05d', 42);                     // "00042" — дополнить нулями до 5 знаков
sprintf('%-10s|', 'латте');               // "латте|" — БЕЗ дополнения: ширина в sprintf считается в БАЙТАХ, а "латте" уже 10 байт в UTF-8 (5 букв × 2 байта)
sprintf('%-15s|', 'латте');               // "латте     |" — а вот тут дополнение видно: до 15 байт не хватает 5, они и стали пробелами
sprintf('%1$s стоит %2$d ₽, скидка на %1$s — 10%%', 'латте', 250);   // позиционные аргументы: %1$s переиспользуется; %% — литеральный процент

4.3 preg_* — регулярные выражения

preg_match('/^\d{3}-\d{4}$/', '123-4567', $matches);         // 1 (найдено); $matches[0] — вся строка целиком
preg_match_all('/\d+/', 'заказ 5 латте по 250 руб', $all);    // находит ВСЕ числа: $all[0] === ['5', '250']

6. Обработка ошибок: Exception vs Error, хендлеры #

6.1 Иерархия Throwable

Throwable (интерфейс — и Error, и Exception его реализуют; try/catch (Throwable $e) ловит ОБА)
├── Error                              — ошибки уровня движка: то, что раньше "фатально останавливало" скрипт без возможности поймать
│   ├── TypeError                       — несовпадение типа (сработает strict_types из раздела 2!)
│   ├── ValueError                      — валидный тип, невалидное значение (напр. str_split('hello', 0))
│   ├── ArgumentCountError               — не хватает обязательных аргументов
│   └── DivisionByZeroError              — деление на ноль в intdiv() или через %
└── Exception                          — ошибки уровня приложения: то, что ВЫ бросаете намеренно
    ├── RuntimeException                 — ошибка, которую нельзя было предвидеть на этапе написания кода
    ├── LogicException                    — ошибка программиста: неверный вызов API, нарушение контракта
    │   ├── InvalidArgumentException
    │   ├── DomainException
    │   └── OutOfRangeException
    └── ваши собственные: class PaymentFailed extends RuntimeException {}

Практическое правило: Error — то, что почти всегда сигнализирует БАГ в вашем коде (опечатка в типе, обращение к несуществующему методу) — ловить его стоит только на самом верхнем уровне (global handler) для логирования, не для восстановления работы. Exception — то, что вы бросаете и ловите осознанно как часть бизнес-логики (недостаточно средств, неверный формат, товар закончился) — тот же принцип, что Result<T, E> в TS-лабе или доменные исключения в ООП-лабе.

6.2 try/catch/finally и порядок ловли

<?php
declare(strict_types=1);

function chargeCard(float $amount): string
{
    if ($amount <= 0) throw new InvalidArgumentException('сумма должна быть положительной');
    if ($amount > 100000) throw new RuntimeException('превышен лимит');
    return 'auth-' . bin2hex(random_bytes(4));
}

try {
    echo chargeCard(-10);
} catch (InvalidArgumentException $e) {                 // СПЕЦИФИЧНОЕ исключение — раньше, чем общее
    echo 'Некорректный ввод: ' . $e->getMessage();
} catch (RuntimeException $e) {                            // общее — позже
    echo 'Ошибка выполнения: ' . $e->getMessage();
} finally {
    echo 'Логируем попытку оплаты в любом случае';        // выполнится ВСЕГДА — и при успехе, и при исключении, и даже при return внутри try
}

// ловля НЕСКОЛЬКИХ типов одним catch (PHP 8+)
try { chargeCard(-5); }
catch (InvalidArgumentException | RuntimeException $e) { echo $e->getMessage(); }

6.4 set_error_handler и set_exception_handler — последняя линия обороны

<?php
declare(strict_types=1);

    // ловит E_WARNING, E_NOTICE и подобные "старые" ошибки (не Error/Exception!) — превращает их в исключение
    throw new ErrorException($message, 0, $severity, $file, $line);
});

set_exception_handler(function (Throwable $e): void {          // последний рубеж — если исключение долетело досюда, никто его не поймал
    http_response_code(500);
    error_log($e->getMessage() . ' в ' . $e->getFile() . ':' . $e->getLine());

});

// теперь даже "старая" ошибка становится исключением и ловится глобально:
echo $undefinedVariable;    // Warning превращается в ErrorException → set_exception_handler → JSON-ответ 500
Зачем: set_error_handler закрывает разрыв между старым стилем PHP-ошибок (warnings, notices — не Throwable, их нельзя поймать через try/catch) и современными исключениями: превращая их в ErrorException, вы получаете единую точку обработки. set_exception_handler — ровно то место, куда Laravel помещает свой Handler::render() из ООП-лабы и Laravel-лабы (раздел 4.3 Laravel-лабы, withExceptions) — просто без обёртки фреймворка, голыми руками.

7. Замыкания, callable, стрелочные функции #

7.1 use — замыкание должно ЯВНО захватить переменную

В отличие от JS (JS-лаба, раздел 6 — любая внешняя переменная автоматически доступна внутри замыкания), в PHP анонимная функция ничего не видит снаружи по умолчанию — нужно явно перечислить, что захватить, через use.

<?php
declare(strict_types=1);

$discountPercent = 10;

$withDiscount = function (float $price) use ($discountPercent): float {   // явный захват — без use код бы не скомпилировался
    return $price * (1 - $discountPercent / 100);
};
echo $withDiscount(250);           // 225

// use ($var) — копия ЗНАЧЕНИЯ на момент СОЗДАНИЯ замыкания, не на момент вызова!
$discountPercent = 50;
echo $withDiscount(250);            // ВСЁ ЕЩЁ 225 — замыкание захватило 10%, изменение снаружи его не коснулось

// use (&$var) — захват ПО ССЫЛКЕ, видит последующие изменения
$counter = 0;
$increment = function () use (&$counter): void { $counter++; };
$increment(); $increment(); $increment();
echo $counter;                       // 3
🔬 Под капотом: use по значению vs use по ссылке — прямая параллель с var-в-цикле из JS-лабы

Захват use ($var) в PHP делает КОПИЮ значения в момент, когда объявляется замыкание — это устраняет баг «var в цикле» из JS-лабы (раздел 1 JS-лабы) АВТОМАТИЧЕСКИ: foreach ($items as $item) { $callbacks[] = function() use ($item) { echo $item; }; } — каждое замыкание получает свою копию $item на момент создания, аналогично тому, как let в JS создаёт новую переменную на итерации. Проблема была бы, если бы использовали use (&$item) — тогда все замыкания делили бы одну ссылку, и результат совпал бы с багом var из JS-лабы.

7.2 Стрелочные функции (fn) — автоматический захват

$discountPercent = 10;
$withDiscount = fn(float $price): float => $price * (1 - $discountPercent / 100);   // автоматически "видит" $discountPercent, БЕЗ use
// но: только для ОДНОГО выражения, без {} и без нескольких строк — для сложной логики нужна обычная function

7.3 callable: четыре формы одного типа

function applyToAll(array $items, callable $fn): array { return array_map($fn, $items); }

applyToAll([1, 2, 3], fn($x) => $x * 2);                   // 1. стрелочная функция

8. Генераторы, Iterator, ленивые вычисления #

8.1 yield — функция, которая приостанавливается и продолжается

<?php
declare(strict_types=1);

function readLargeFile(string $path): Generator {
    $handle = fopen($path, 'r');
    while (($line = fgets($handle)) !== false) {
        yield trim($line);           // "выдать" строку и ПРИОСТАНОВИТЬСЯ — файл читается по одной строке, а не целиком в память
    }
    fclose($handle);
}

foreach (readLargeFile('orders.csv') as $line) {
    echo $line, "\n";
    if ($line === 'STOP') break;      // прекращаем читать файл в ЛЮБОЙ момент — оставшиеся гигабайты даже не тронуты
}

Вызов readLargeFile('orders.csv') НЕ читает файл сразу — он возвращает объект Generator мгновенно; код внутри функции выполняется по одной итерации foreach за раз. На файле в 10 ГБ обычная функция, вернувшая бы массив всех строк, съела бы 10+ ГБ памяти; генератор — единицы килобайт, независимо от размера файла.

8.3 Iterator и IteratorAggregate — свой перебираемый объект

Прямая параллель Symbol.iterator из JS-лабы (раздел 8): интерфейс, который делает объект совместимым с foreach.

<?php

final class OrderCollection implements IteratorAggregate, Countable
{
    /** @var Order[] */
    private array $orders = [];

    public function add(Order $order): void { $this->orders[] = $order; }

    public function getIterator(): Iterator { return new ArrayIterator($this->orders); }   // делегируем готовому итератору

    public function count(): int { return count($this->orders); }                            // Countable — работает count($collection)
}

$collection->add(new Order('Эспрессо', 150));

Зачем: IteratorAggregate проще в реализации, чем Iterator напрямую (не нужно вручную писать current()/next()/key()/valid()/rewind() — пять методов), если у вас уже есть готовая структура для делегирования (ArrayIterator оборачивает обычный массив). 9.2 __call и __callStatic: как работают фасады

<?php
declare(strict_types=1);

final class QueryBuilder
{
    private array $wheres = [];

    public function where(string $column, mixed $value): static
    {
        $this->wheres[] = [$column, $value];
        return $this;
    }

    public function __call(string $name, array $args): static     // ловит whereStatus(), whereTitle() — ЛЮБОЙ несуществующий метод
    {
        if (str_starts_with($name, 'where')) {
            $column = lcfirst(substr($name, 5));                    // whereStatus → status
            return $this->where($column, $args[0]);
        }
        throw new BadMethodCallException("метод {$name} не существует");
    }
}

$query = new QueryBuilder();
$query->whereStatus('open')->whereTitle('Латте');       // ни whereStatus, ни whereTitle физически не существуют как методы!

// __callStatic — механизм ВСЕХ фасадов Laravel:
final class Cache
{
    private static ?ArrayAccess $resolvedInstance = null;

    public static function __callStatic(string $name, array $args): mixed
    {
        self::$resolvedInstance ??= app('cache');            // резолвим РЕАЛЬНЫЙ объект из контейнера один раз
        return self::$resolvedInstance->$name(...$args);        // и вызываем у него настоящий метод
    }
}
Cache::get('key');       // Cache::get физически не существует — это __callStatic → $resolvedInstance->get('key')
Зачем: Это буквально то, что происходит внутри Illuminate\Support\Facades\Facade — упрощено до сути. getFacadeAccessor() у реального фасада возвращает строку типа 'cache', которую app() резолвит из контейнера (Laravel-лаба, раздел 5), а __callStatic перенаправляет вызов на реальный объект. Теперь, увидев Cache::remember(...), вы знаете: это не «специальная синтаксическая конструкция», это ровно тот код, что вы только что написали, только в вендоре.

// switch: без break — "проваливается" в следующий case (частый источник багов); сравнение НЕСТРОГОЕ (==)
switch ($status) {
    case 'open': $label = 'Открыт'; break;
    case 'closed': $label = 'Закрыт'; break;
    default: $label = 'Неизвестно';
}

// match: строгое сравнение (===), НЕТ проваливания, возвращает значение, обязателен default (или UnhandledMatchError)
$label = match ($status) {
    'open' => 'Открыт',
    'closed', 'archived' => 'Закрыт',        // несколько условий через запятую — ОДНА стрелка
    default => 'Неизвестно',
};

// match БЕЗ аргумента — цепочка условий (замена длинному if/elseif)
$discount = match (true) {
    $total > 1000 => 0.15,
    $total > 500 => 0.10,
    default => 0,
};

// UnhandledMatchError — если убрать default и статус не совпадёт ни с одним вариантом
$label = match ($status) {
    'open' => 'Открыт',
};                                            // 'closed' → UnhandledMatchError: Unhandled match case 'closed'

10.2 Nullsafe оператор ?-> и null coalescing ??/??=

$city = $order?->customer?->address?->city;      // если ЛЮБОЕ звено цепочки null — весь результат null, БЕЗ фатальной ошибки
// эквивалент ДО PHP 8:
$city = null;
if ($order !== null && $order->customer !== null && $order->customer->address !== null) {
    $city = $order->customer->address->city;
}

$name = $data['name'] ?? 'Гость';                  // если ключа нет ИЛИ значение null — взять дефолт (не бросает Notice)
$config['timeout'] ??= 30;                            // присвоить, ТОЛЬКО ЕСЛИ ещё не установлено (null coalescing assignment)
🔬 Под капотом: ?-> останавливается на ПЕРВОМ null, а не проверяет все звенья

$order?->customer?->address?->city — если $order уже null, движок даже не пытается обратиться к ->customer: вся цепочка справа от первого null-звена просто не вычисляется (short-circuit), возвращается null целиком. Это отличается от гипотетического «проверить все поля на null и потом собрать» — вычисление останавливается на первом же провале, как && в булевых выражениях.

11.2 composer.json и PSR-4

{
    "name": "vanilla/coffee-shop",
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    }
}

PSR-4 — соглашение: namespace App\Domain\Drink соответствует файлу src/Domain/Drink.php (префикс App\ отброшен, остаток namespace — путь к папке, имя класса — имя файла). Composer генерирует автозагрузчик, который при первом обращении к неизвестному классу вычисляет путь по этому правилу и делает require сам.

composer dump-autoload            # сгенерировать/обновить vendor/autoload.php

11.3 spl_autoload_register — как это устроено внутри

<?php
declare(strict_types=1);

spl_autoload_register(function (string $class): void {
    $prefix = 'App';
    if (!str_starts_with($class, $prefix)) return;                 // не наш namespace — пусть пробует следующий зарегистрированный autoloader

    $relative = substr($class, strlen($prefix) + 1);                 // App\Domain\Drink → Domain\Drink (+1 — пропускаем сам разделитель \)
    $path = __DIR__ . '/src/' . str_replace('\\', '/', $relative) . '.php';   // Domain\Drink → Domain/Drink.php

    if (file_exists($path)) require $path;
});

// теперь:
$drink = new App\Domain\Drink('Латте', 250);      // класс НИКОГДА не был require'нут явно — autoloader нашёл файл сам, ПРИ ПЕРВОМ обращении
Зачем: spl_autoload_register — единственный низкоуровневый механизм, на котором построена ЛЮБАЯ автозагрузка в PHP, включая ту, что генерирует Composer. Функция вызывается движком в момент, когда встречается имя класса, для которого ещё нет объявления, — и делает ровно то же самое, что вы только что написали руками: вычисляет путь по правилу и подключает файл. Composer добавляет к этому оптимизации (classmap для продакшена — таблица класс→файл, построенная заранее, без вычисления пути на каждый запрос) и поддержку нескольких правил одновременно (PSR-4, PSR-0, classmap, files).

Шаг 2.1Copy-on-write вживую: измеряем момент физического копирования#

Copy-on-write — не абстракция, а измеримый момент времени. Используем memory_get_usage(), чтобы увидеть его своими глазами.

<?php
declare(strict_types=1);
// src/03_cow.php

function mb(): string { return number_format(memory_get_usage() / 1024, 1) . ' KB'; }

echo "до создания массива: " . mb() . "\n";
$a = range(1, 500000);                          // большой массив — 500 тысяч элементов
echo "после создания \$a: " . mb() . "\n";

$b = $a;                                          // "копия" — но memory_get_usage НЕ должен вырасти заметно!
echo "после \$b = \$a (ДО изменения): " . mb() . "\n";

$b[0] = 'изменено';                                // ВОТ ЗДЕСЬ происходит физическое копирование — copy-on-write сработал
echo "после \$b[0] = ... (ПОСЛЕ изменения): " . mb() . "\n";

var_dump($a[0]);            // 1 — оригинал НЕ пострадал
var_dump($b[0]);             // "изменено"

Шаг 2.2array_filter сохраняет ключи, usort мутирует и сбрасывает — на данных кофейни#

Функции массивов на данных кофейни — с явным вниманием к сохранению/сбросу ключей, которое путает почти всех новичков.

<?php
declare(strict_types=1);
// src/04_arrays.php

$drinks = [
    ['name' => 'Эспрессо', 'price' => 150, 'category' => 'coffee'],
    ['name' => 'Латте', 'price' => 250, 'category' => 'coffee'],
    ['name' => 'Капучино', 'price' => 230, 'category' => 'coffee'],
    ['name' => 'Чай', 'price' => 120, 'category' => 'tea'],
];

// array_column — вытащить один столбец, опционально с ключом
$names = array_column($drinks, 'name');
$priceByName = array_column($drinks, 'price', 'name');
print_r($names);
print_r($priceByName);

// array_filter СОХРАНЯЕТ ключи — классическая ловушка
$coffeeOnly = array_filter($drinks, fn($d) => $d['category'] === 'coffee');
var_dump(array_keys($coffeeOnly));           // [0, 1, 2] — чай был под ключом 3, он удалён, но 0,1,2 остались КАК БЫЛИ
$coffeeOnlyReindexed = array_values($coffeeOnly);   // ТЕПЕРЬ [0, 1, 2] заново — array_values сбрасывает ключи

// usort МУТИРУЕТ и СБРАСЫВАЕТ ключи (в отличие от array_filter)
$sorted = $drinks;                              // копия перед сортировкой (COW!) — не трогаем оригинал
usort($sorted, fn($a, $b) => $a['price'] <=> $b['price']);
echo $sorted[0]['name'], "\n";                    // Чай — 120, самый дешёвый

// array_reduce — сумма и группировка одновременно через массив-аккумулятор
$totals = array_reduce($drinks, function (array $carry, array $d): array {
    $carry['sum'] = ($carry['sum'] ?? 0) + $d['price'];
    $carry['byCategory'][$d['category']][] = $d['name'];
    return $carry;
}, []);
print_r($totals);

Шаг 3.3Предскажи порядок finally vs exception handler, потом проверь#

Глобальный exception handler — предскажите порядок вывода ПЕРЕД запуском: что попадёт в HTTP-ответ, что — в лог сервера, и в каком порядке выполнится finally относительно них.

<?php
declare(strict_types=1);
// public/errors.php

final class InsufficientStockException extends RuntimeException
{
    public function __construct(public readonly string $drink, public readonly int $available)
    {
        parent::__construct("Недостаточно \"{$drink}\": доступно {$available}");
    }
}

set_exception_handler(function (Throwable $e): void {
    http_response_code($e instanceof InsufficientStockException ? 409 : 500);
    error_log('[EXCEPTION] ' . $e->getMessage());                      // видно в docker compose logs, НЕ в ответе клиенту
    header('Content-Type: application/json; charset=utf-8');
    echo json_encode([
        'error' => $e instanceof InsufficientStockException ? $e->getMessage() : 'Внутренняя ошибка сервера',   // детали ТОЛЬКО для ожидаемых исключений
    ], JSON_UNESCAPED_UNICODE);
});

function reserveStock(string $drink, int $requested, int $available): void
{
    if ($requested > $available) {
        throw new InsufficientStockException($drink, $available);
    }
    echo json_encode(['reserved' => $requested]);
}

$requested = (int) ($_GET['qty'] ?? 1);

try {
    reserveStock($drink, $requested, available: 3);
} finally {
    error_log('[FINALLY] попытка резервирования обработана');            // выполнится ВСЕГДА — до того, как исключение долетит до handler'а!
}

    while (($row = fgetcsv($handle)) !== false) {
        yield $row;

    fclose($handle);
}

        }
        return self::$instance->$name(...$args);               // делегируем вызов
    }
}

<?php
declare(strict_types=1);
// src/Http/Router.php — ВЕРСИЯ 2: с параметрами через regex, ПОЛНОСТЬЮ переписан

namespace App\Http;

final class Router
{
    private array $routes = [];      // [['method'=>.., 'pattern'=>Regex, 'paramNames'=>[...], 'handler'=>callable]]

    public function get(string $path, callable $handler): void  { $this->add('GET', $path, $handler); }
    public function post(string $path, callable $handler): void { $this->add('POST', $path, $handler); }

    private function add(string $method, string $path, callable $handler): void
    {
        $paramNames = [];
        $pattern = preg_replace_callback('#\{(\w+)\}#', function ($m) use (&$paramNames) {
            $paramNames[] = $m[1];
            return '([^/]+)';                                     // {id} → захватывающая группа "всё, кроме /"
        }, $path);
        $this->routes[] = ['method' => $method, 'pattern' => '#^' . $pattern . '$#', 'paramNames' => $paramNames, 'handler' => $handler];
    }

    public function dispatch(string $method, string $uri): mixed
    {
        $path = parse_url($uri, PHP_URL_PATH) ?? '/';               // отбросить query-строку (?a=1) — она не часть пути
        foreach ($this->routes as $route) {
            if ($route['method'] !== $method) continue;
            if (preg_match($route['pattern'], $path, $matches)) {
                $params = array_combine($route['paramNames'], array_slice($matches, 1));   // array_column-подобная сборка ключ=>значение
                return ($route['handler'])($params);
            }
        }
        http_response_code(404);
        return ['error' => 'Not Found'];
    }
}

Шаг 6.3Контейнер v2: настоящий autowiring через ReflectionClass — параллель с Laravel Container#

Версия 2 — настоящий autowiring через Reflection: контейнер САМ читает конструктор класса и резолвит зависимости по типам, без единой явной фабрики для классов без интерфейсов.

<?php
declare(strict_types=1);
// src/Container/Container.php — ВЕРСИЯ 2: autowiring через Reflection, полностью переписан

namespace App\Container;

final class Container
{
    private array $bindings = [];
    private array $instances = [];

    public function bind(string $abstract, string|callable $concrete): void { $this->bindings[$abstract] = $concrete; }

    public function singleton(string $abstract, string|callable $concrete): void
    {
        $this->bind($abstract, function (Container $c) use ($abstract, $concrete) {
            return $this->instances[$abstract] ??= $this->build($concrete, $c);
        });
    }

    public function make(string $name): mixed
    {
        if (isset($this->bindings[$name])) {
            $concrete = $this->bindings[$name];
            return is_callable($concrete) ? $concrete($this) : $this->build($concrete, $this);
        }
        return $this->build($name, $this);                          // НЕТ явного биндинга? Пробуем построить через Reflection напрямую
    }

    private function build(string|callable $concrete, Container $c): mixed
    {
        if (is_callable($concrete) && !is_string($concrete)) return $concrete($c);

        $reflection = new \ReflectionClass($concrete);
        if (!$reflection->isInstantiable()) {
            throw new \RuntimeException("{$concrete} нельзя создать напрямую — это интерфейс или abstract класс. Нужен явный bind().");
        }

        $constructor = $reflection->getConstructor();
        if ($constructor === null) return new $concrete();            // нет конструктора — нет зависимостей, создаём напрямую

        $dependencies = [];
        foreach ($constructor->getParameters() as $param) {
            $type = $param->getType();
            if ($type === null || $type->isBuiltin()) {                  // скалярный тип (int, string) — Reflection не может его "угадать"
                if ($param->isDefaultValueAvailable()) {
                    $dependencies[] = $param->getDefaultValue();
                    continue;
                }
                throw new \RuntimeException("Не могу разрешить параметр \${$param->getName()} без явного значения или дефолта");
            }
            $dependencies[] = $this->make($type->getName());              // РЕКУРСИЯ: зависимость может сама иметь зависимости
        }
        return $reflection->newInstanceArgs($dependencies);
    }
}

Шаг 7.2Транзакция: предсказать поведение rollBack после частично выполненных операций#

Транзакция — предскажите поведение при ошибке ПОСЕРЕДИНЕ операции, затем проверьте на реальных данных.

<?php
declare(strict_types=1);
// src/17_transactions.php

$pdo = new PDO('pgsql:host=postgres;dbname=coffee', 'coffee', 'coffee', [PDO::ATTR_ERRMODE => PDO::ERRMODE_EXCEPTION]);

function reserveStock(PDO $pdo, string $drinkName, int $qty): void
{
    $pdo->beginTransaction();
    try {
        $stmt = $pdo->prepare('SELECT price FROM drinks WHERE name = :name FOR UPDATE');   // FOR UPDATE — блокировка строки на время транзакции
        $stmt->execute(['name' => $drinkName]);
        $price = $stmt->fetchColumn();
        if ($price === false) throw new RuntimeException("Напиток {$drinkName} не найден");

        $pdo->prepare('INSERT INTO orders (drink_name, qty, total) VALUES (:name, :qty, :total)')
            ->execute(['name' => $drinkName, 'qty' => $qty, 'total' => $price * $qty]);

        if ($qty > 100) throw new RuntimeException('подозрительно большое количество');    // ИСКУССТВЕННЫЙ сбой ПОСЛЕ вставки заказа

        $pdo->commit();
        echo "Заказ создан\n";
    } catch (Throwable $e) {
        $pdo->rollBack();                                          // предскажите: останется ли запись в orders после rollBack?
        echo "Откат: {$e->getMessage()}\n";
    }
}

reserveStock($pdo, 'Латте', 2);          // обычный случай — должен пройти
reserveStock($pdo, 'Латте', 200);         // искусственный сбой ПОСЛЕ INSERT — предскажите итог

Шаг 7.3CSRF-токен своими руками: сессия, hash_equals, форма + проверка#

CSRF-токен руками — то, что скрыто за @csrf в Blade. Собираем по шагам: сначала форма БЕЗ защиты (уязвима), потом с токеном.

<?php
declare(strict_types=1);
// src/Support/Csrf.php

namespace App\Support;

final class Csrf
{
    public static function token(): string
    {
        session_start();                                        // идемпотентно — если сессия уже стартовала, ничего не сломает
        return $_SESSION['csrf_token'] ??= bin2hex(random_bytes(32));   // сгенерировать ОДИН раз на сессию, переиспользовать
    }

    public static function verify(?string $submitted): bool
    {
        session_start();
        $expected = $_SESSION['csrf_token'] ?? null;
        return $expected !== null && $submitted !== null && hash_equals($expected, $submitted);   // hash_equals — защита от timing-атак
    }
}

    public static function load(string $path): void
    {
        if (!file_exists($path)) return;

    {
        $body = json_decode(file_get_contents('php://input'), associative: true) ?? [];
        $drinkId = (int) ($body['drink_id'] ?? 0);
        $qty = (int) ($body['qty'] ?? 0);

        if ($drinkId <= 0 || $qty <= 0) {
            Response::json(['error' => 'drink_id и qty обязательны и должны быть положительными'], 422);
        }

        $this->db->beginTransaction();
        try {
            $stmt = $this->db->prepare('SELECT price FROM drinks WHERE id = :id FOR UPDATE');
            $stmt->execute(['id' => $drinkId]);
            $price = $stmt->fetchColumn();
            if ($price === false) { $this->db->rollBack(); Response::json(['error' => 'Напиток не найден'], 404); }

            $total = $price * $qty;
            $this->db->prepare('INSERT INTO orders (drink_id, qty, total) VALUES (:d, :q, :t)')
                ->execute(['d' => $drinkId, 'q' => $qty, 't' => $total]);
            $this->db->commit();

            Response::json(['order' => ['drink_id' => $drinkId, 'qty' => $qty, 'total' => $total]], 201);
        } catch (\Throwable $e) {
            $this->db->rollBack();
            Response::json(['error' => 'Не удалось создать заказ'], 500);
        }
    }

    public function index(array $params): never
    {
        $stmt = $this->db->query('SELECT o.*, d.name AS drink_name FROM orders o JOIN drinks d ON d.id = o.drink_id ORDER BY o.created_at DESC');
        Response::json($stmt->fetchAll());
    }
}

Шаг 8.2Middleware-цепочка через array_reduce: предсказать порядок "матрёшки", потом проверить#

Middleware-цепочка своими руками — та же идея Decorator, что в Laravel-лабе (раздел 6 Laravel-лабы), но собранная руками из массива callable.

<?php
declare(strict_types=1);
// src/Http/Router.php — ДОБАВИТЬ поддержку middleware

namespace App\Http;

final class Router
{
    private array $routes = [];
    private array $globalMiddleware = [];

    public function middleware(callable $mw): void { $this->globalMiddleware[] = $mw; }

    // ... get()/post()/add() как в 5.2, плюс сохранение $middleware для конкретного маршрута ...

    public function dispatch(string $method, string $uri): mixed
    {
        $path = parse_url($uri, PHP_URL_PATH) ?? '/';
        foreach ($this->routes as $route) {
            if ($route['method'] !== $method) continue;
            if (preg_match($route['pattern'], $path, $matches)) {
                $params = array_combine($route['paramNames'], array_slice($matches, 1));

                $pipeline = array_reduce(                              // строим ВЛОЖЕННЫЕ замыкания из middleware, ИЗНУТРИ НАРУЖУ
                    array_reverse($this->globalMiddleware),
                    fn($next, $mw) => fn($params) => $mw($params, $next),
                    $route['handler'],                                    // самый внутренний слой — сам обработчик маршрута
                );
                return $pipeline($params);
            }
        }
        http_response_code(404);
        return ['error' => 'Not Found'];
    }
}

Прежде чем читать дальше — предскажите порядок вывода при ДВУХ middleware (A и B, в этом порядке регистрации) вокруг обработчика H: A выполнится до или после B? "До" H или "после" H, и в каком порядке "до"/"после" для A и B?

<?php

declare(strict_types=1);

function middlewareA($params, $next) { echo "A: до\n"; $result = $next($params); echo "A: после\n"; return $result; }
function middlewareB($params, $next) { echo "B: до\n"; $result = $next($params); echo "B: после\n"; return $result; }
function handler($params) { echo "H: обработчик\n"; return 'готово'; }

$pipeline = array_reduce(
    array_reverse(['middlewareA', 'middlewareB']),
    fn($next, $mw) => fn($params) => $mw($params, $next),
    'handler',
);
$pipeline([]);

Порядок «матрёшкой»: A регистрировался ПЕРВЫМ, поэтому оборачивает всё остальное СНАРУЖИ — его код «до» выполняется первым, а код «после» — последним. Если ваше предсказание совпало — вы правильно поняли механизм вложенных замыканий; если нет, перечитайте array_reduce с array_reverse ещё раз, посимвольно проследив, что происходит на каждой итерации.

Зачем: array_reduce с array_reverse строит цепочку замыканий ИЗНУТРИ НАРУЖУ: начинаем с handler как самого внутреннего слоя, оборачиваем его в middlewareB (последний в исходном порядке — обрабатывается первым при reverse), затем результат оборачиваем в middlewareA. Итоговый $pipeline — это middlewareA, внутри которого при вызове $next() находится middlewareB, внутри которого — сам handler. Это ТОЧНО тот же паттерн Pipeline, что использует Laravel для HTTP-middleware (Laravel-лаба, раздел 6.1: Pipeline::through([...])->then(...)) — вы только что построили его упрощённую версию руками.

declare(strict_types=1) — директива файла, отключающая неявное приведение типов при вызовах функций ИЗ ЭТОГО файла.
TypeError — исключение (точнее, Error) при несовпадении типа аргумента/возврата под strict_types.
Copy-on-write (COW) — оптимизация: массив физически копируется не при присваивании, а при первой попытке изменить одну из копий.
array_filter / usort — фильтрация с сохранением ключей / сортировка с мутацией и сбросом ключей.
mb_* функции — multibyte-безопасные аналоги строковых функций (mb_strlen, mb_substr), корректно работающие с UTF-8.
Суперглобалы — $_GET, $_POST, $_SERVER, $_SESSION, $_COOKIE, $_ENV — глобальные массивы данных запроса.
php://input — поток для чтения сырого тела HTTP-запроса; единственный способ получить JSON-тело.
Throwable / Error / Exception — корневой интерфейс исключений; Error — ошибки движка, Exception — ошибки приложения.
set_exception_handler — глобальный перехватчик непойманных исключений — последняя линия обороны.
Closure / use — анонимная функция; use — явный захват внешней переменной (по значению или по ссылке через &).
Стрелочная функция (fn) — короткий синтаксис с автоматическим захватом внешних переменных, только для одного выражения.
callable — псевдотип для всего, что можно вызвать: функция, замыкание, [объект, метод], [класс, метод].
Generator / yield — функция, приостанавливающаяся на yield и продолжающаяся при следующей итерации — ленивые вычисления.
Iterator / IteratorAggregate — интерфейсы, делающие объект совместимым с foreach.
Магические методы — __get/__set/__call/__callStatic/__invoke/__toString и др. — перехватчики операций над объектом.
Фасад (через __callStatic) — статический прокси к объекту из контейнера/реестра — механизм Cache::, Log:: и подобных в Laravel.
match — выражение-переключатель со строгим сравнением, без проваливания, обязательно исчерпывающее.
Nullsafe (?->) — обращение к свойству/методу, останавливающееся на null без ошибки — short-circuit по цепочке.
PSR-4 — стандарт соответствия namespace класса и пути к файлу для автозагрузки.
spl_autoload_register — низкоуровневая функция регистрации автозагрузчика; основа composer-автозагрузки.
PDO — абстракция доступа к БД; prepared statements разделяют SQL-текст и данные, защищая от инъекций.
Транзакция (beginTransaction/commit/rollBack) — группа операций, применяемая целиком или не применяемая вообще.

hash_equals — сравнение строк за константное время — защита от timing-атак при сверке секретов.
CSRF-токен — секретное значение, привязанное к сессии, подтверждающее, что запрос пришёл с легитимной формы.
DI-контейнер / autowiring — реестр объектов приложения; autowiring — автоматическое разрешение зависимостей конструктора через Reflection.
ReflectionClass — API для интроспекции класса в рантайме: чтение конструктора, параметров, типов.
